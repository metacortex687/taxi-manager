# Нагрузочные сценарии

Каталог содержит сценарии нагрузочного тестирования Taxi-manager, реализованные с помощью k6. Они используются для исследования поведения REST API при чтении, создании и удалении данных, а также для оценки зависимости задержек от интенсивности запросов.

Итоги проведённых экспериментов и их интерпретация приведены в разделе [«Нагрузочное тестирование»](../README.md#нагрузочное-тестирование) основного README.

## Сценарии

| Файл | Назначение |
| --- | --- |
| `load_test.js` | Универсальный GET-тест с настраиваемыми числом виртуальных пользователей, количеством итераций и паузой между запросами. |
| `load_test_rps_ladder_simple.js` | Последовательно увеличивает интенсивность GET-запросов и используется для анализа задержек и ошибок на разных уровнях RPS. |
| `load_test_models_read.js` | Читает модели автомобилей по идентификатору со ступенчатым увеличением интенсивности запросов. |
| `load_test_models_write.js` | Создаёт тестовые модели автомобилей со ступенчатым увеличением интенсивности запросов. Перед запуском удаляет ранее созданные тестовые данные. |
| `load_test_models_delete.js` | Удаляет тестовые модели автомобилей со ступенчатым увеличением интенсивности запросов. После завершения очищает оставшиеся тестовые данные. |
| `models_common.js` | Содержит общие адреса REST API, заголовки авторизации, тела запросов, теги метрик и вспомогательные функции сценариев моделей автомобилей. |

## Настройка

Параметры цели нагрузки задаются в файле `.load-testing.env`. В качестве основы используется [`.load-testing.env.default`](../.load-testing.env.default):

```dotenv
TARGET_BASE_URL=http://nginx
TARGET_PATH=/api/v1/vehicles/10/trip-points/?response_format=geojson&id=291
AUTH_TOKEN=replace_me
```

- `TARGET_BASE_URL` — базовый адрес тестируемого приложения;
- `TARGET_PATH` — путь для универсальных GET-сценариев;
- `AUTH_TOKEN` — токен авторизации REST API.

Сценарии работы с моделями автомобилей используют адреса, определённые в `models_common.js`. Переменная `MODEL_URL` выбирает исследуемую реализацию REST API.

## Запуск

Сценарий выбирается переменной `K6_SCRIPT`. По умолчанию используется `load_test_rps_ladder_simple.js`.

Запуск вместе с расширенным окружением Taxi-manager и локальным стеком наблюдаемости:

```bash
make perf-dev K6_SCRIPT=load_test_rps_ladder_simple.js
```

Примеры запуска сценариев моделей автомобилей:

```bash
make perf-dev K6_SCRIPT=load_test_models_write.js
make perf-dev K6_SCRIPT=load_test_models_read.js
make perf-dev K6_SCRIPT=load_test_models_delete.js
```

Для отдельного окружения наблюдаемости используется команда:

```bash
make perf-f-observ K6_SCRIPT=load_test_rps_ladder_simple.js
```

k6 передаёт метрики в Prometheus через remote write. Для анализа используются Grafana и дашборд [`load-testing-current-source-metrics.json`](../grafana/dashboards/load-testing-current-source-metrics.json).

## Тестовые данные

Сценарии создания и удаления используют префикс `perf_test_model_`. Они обращаются к служебной операции очистки тестовых данных, поэтому их следует запускать только в тестовом окружении.

Сценарий чтения ожидает, что тестовые модели уже созданы. Обычно сначала выполняется `load_test_models_write.js`, затем — `load_test_models_read.js` или `load_test_models_delete.js`.
