# 1. Переносить в Rust только измеренные узкие места

Date: 2026-08-18

## Status

Accepted

## Context

Основная бизнес-логика Taxi-manager реализована в Django. По мере развития
проекта отдельные операции могут перестать удовлетворять требованиям к
производительности. Полный перенос приложения на другой технологический стек
увеличил бы сложность проекта и стоимость сопровождения без подтверждённой
необходимости.

## Decision

Сохранять Django основным приложением и переносить в Rust API только те операции,
которые по результатам измерений выявлены как узкие места по производительности.

Rust API напрямую работает с общей базой PostgreSQL и должен учитывать схему,
управляемую миграциями Django. На текущем этапе он читает и создаёт записи
`vehicle_model`, поддерживая одиночные и пакетируемые обращения.

## Consequences

- оптимизация выполняется на основании измерений, а не предположений;
- основная бизнес-логика и управление схемой базы данных остаются в Django;
- Rust API можно развивать постепенно по мере обнаружения новых узких мест;
- прямой доступ двух приложений к общей схеме усиливает связанность, поэтому
  изменения моделей Django должны проверяться на совместимость с Rust API.
